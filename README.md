# STS

LÖVE (Love2D) エンジンを使用して開発中の、デッキ構築型ローグライクゲームのプロトタイプです。
まだ作成中のため、実行ファイル（ビルド）は用意しておらず、ソースコードのみの公開となります。

## ゲームの概要
敵の肉体に憑依し、自身の寿命（最大HP）を削りながら迷宮を進んでいくカードゲームです。

* **憑依システム**: 倒した敵の肉体を奪い、その敵が持っていたデッキを使用して戦います。
* **マスタリー**: 特定の条件を満たして敵を倒すことで、強力なカードを自身の「魂」に永続的に刻み込むことができます。
* **寿命と劣化**: 毎ターン最大HPが減少していくため、リソース管理と素早い決着が求められます。

## ファイル構成
* `main.lua` : ゲーム全体の進行（マップ、キャンプ、イベント、UI遷移）管理
* `battle.lua` : 戦闘ロジック（ターン進行、カード効果、マスタリー判定）の分離モジュール
* `deck_viewer.lua` : デッキや捨て札を閲覧するUIモジュール
* `map.lua` : マップのノード生成と進行判定
* `enemy.lua` / `enemies.lua` : 敵のAIとステータスデータ
* `cards.lua` : カードの基礎データと効果定義

## AI活用メモ
本プロトタイプの開発において、開発速度の向上と仕様の壁打ちを目的に生成AIを活用しました。

1. **仕様の壁打ちとロジック構築**
「敵に憑依し寿命を削る」という独自システムの矛盾点や改善点をAIと議論し、「デッキ圧縮のための休憩所」などの仕様を固めました。

2. **ベース実装とリファクタリング**
LÖVEエンジンの基礎仕様に不慣れだったため、ベースとなるコードの記述を任せることで初動の時間を短縮しました。また、開発途中でコードが肥大化した際、戦闘ロジックを別ファイル（battle.lua）に切り出すリファクタリングのサポートを受け、保守性を高めました。

3. **デバッグの効率化**
進行不能バグやマスタリーの二重カウントなど、複雑な状態遷移で起きたエラーの原因特定にAIを活用し、手戻りを最小限に抑えました。

※AIはあくまで提案やサポートの目的で使用しています。出力されたコードをそのまま使うのではなく、「ゲームデザインとして破綻していないか」「コードの意図を自分が完全に理解できているか」を常にAIと話し合い、自分自身でレビューしながら開発を進めています。
